# FALSE POSITIVE RESULT

**Zero false positives on the healthy control; two real false positives found and
fixed on a real run.**

| Test | Result |
|---|---|
| `A0_healthy` (400 steps, ordinary noise) | **0 anomalies** across 6 detectors |
| `A1b` (loss spike, no gradient precursor) | gradient detector correctly silent |
| `A1` real run, first attempt | **2 false positives** at steps 52 and 56 |
| `A1` real run, after fix | 0 false positives; the injected step-80 explosion detected |

The false positives were not threshold noise. The healthy gradient norm is
heavy-tailed — it ranges 1.1–3.3 with unremarkable excursions to 2.8 — so a
Gaussian-style MAD z-score fires on ordinary variation. The fix was to make the
**primary** criterion the one the brief names (change relative to the historical
baseline), implemented as "≥ 3× the largest value in the preceding window", with
the z-score demoted to a secondary criterion and the absolute guard rail retained.

One scenario declares *forbidden* detectors, so precision is pinned by the corpus
and not only by the healthy case.

# OVERHEAD

Measured with 60 warm-up + 60 measured steps × 5 repeats, minimum of per-repeat
medians (contention can only add time). Full detail:
`outputs/phase1/w4/OVERHEAD_SCALING.md`.

```
core observer:     +13.3 % (tiny 4 ms step)  +5.0 % (medium 17 ms)  +3.3 % (large 42 ms)
T1 layer hooks:    +17.9 % (tiny)            +5.4 % (medium)        +3.3 % (large)
```

| Budget | Target | Measured | Verdict |
|---|---|---|---|
| core observer | < 3 % | **+3.3 %** at the largest workload | **FAIL** (marginal) |
| T1 layer hooks | < 8 % | **+3.3 %** at the largest workload | **PASS** at medium and large |

**T1 layer hooks are effectively free**: the incremental cost over core metrics is
0.00–0.02 ms at every size. The budget failure is the core observer, not the layer
instrumentation.

**Absolute cost** — the transferable number — is **+0.6 ms (core) to +1.4 ms (with
T1) per step**.

## What was fixed

The first measurement failed at +80 %. Profiling found real inefficiencies, each
fixed and re-measured:

| Component | Before | After | Factor | Cause |
|---|---|---|---|---|
| `global_gradient_norm` | 826 µs | 169 µs | 4.9× | `.item()` per tensor → one device sync per parameter |
| `global_parameter_norm` | 880 µs | 178 µs | 4.9× | same |
| `LayerMetricCollector.compute` | 35 540 µs | 4 890 µs | 7.3× | same bug, 149 syncs per collected step |
| `observer.emit` | 54.8 µs | 36.7 µs | 1.5× | up to ten `dataclasses.replace` calls |

Two of these are now at the **memory-bandwidth floor**: 4.89 ms ≈ 2.44 (grads) +
2.45 (params) for ~4 M elements. **A gradient norm cannot be computed faster than
it can be read**, so the remaining cost is irreducible at this design.

## Two retracted measurements

1. An early **+7.4 %** figure came from measuring *inside* the sampling policy's
   50-step full-resolution warm-up. Corrected to **+3.3 %**. The earlier number is
   retracted rather than quietly dropped.
2. A median-of-medians estimator produced a **physically impossible** result
   (instrumented faster than baseline). Replaced with minimum-of-medians.

## Remaining levers, not pulled

Halving `grad.global_norm`'s cadence from every 2 steps to every 4 would save
roughly 0.6 ms/step at the largest workload, at the cost of halving the resolution
of the primary gradient signal. Recommended only if a user reports the overhead as
material.

**The small-file problem is answered concretely:** one million events produced
**ten files**. A file-per-event layout would have produced one million — a 100,000×
reduction. The bound is enforced by chunking inside the flush, which was itself a
bug fix: `rows_per_file` originally bounded only the buffer trigger, so one large
batch produced one arbitrarily large file.

End-to-end observer throughput, including validation, sampling, queue and writer
thread: **25,367 events/s, 14.8 µs/event, 0 dropped**.

The 692 ms per-layer query is the honest outlier and is the **first optimisation
if the correlation engine needs many per-layer reads** — the grouping should happen
in DuckDB rather than being materialised through Python.

missed, all fixed:

| Defect | Symptom | Fix |
|---|---|---|

# EARLIEST ABNORMAL EVENT RESULT

**Implemented as required; all three cases tested and passing.**

The earliest abnormal evidence is the **set of minimal elements of the partial
order**. A singular `first_abnormal_event_id` is returned only when that set has
exactly one member **and** no comparison was left unsettled.

| Situation | `first_abnormal_event_id` | `ordering_confidence` | Test |
|---|---|---|---|
| exactly one minimum, no gaps | **set** | `PROVEN` | `test_case_1_unique_earliest_is_proven` |
| one minimum but some comparisons unsettled | set | `LOW` | `test_unique_minimum_with_a_gap_is_low_confidence_not_proven` |
| several minima, all pairs settled | `None` | `PROVEN` (proved concurrent) | `test_case_2_concurrent_candidates_yield_no_single_first` |
| several minima, some pairs unsettled | `None` | `UNKNOWN` | `test_case_3_missing_evidence_yields_unknown_ordering` |

The refusal renders exactly as the brief requires:

> 2 abnormal events are mutually unordered, so no single event can be named first
> … Their exact ordering cannot be established from the available evidence.

`BEFORE` is returned **only** with a witness: `producer_sequence`, `causal_edge`,
or a caller-supplied `barrier`. `event_id` and `wall_time_ns` are never witnesses.

**A producer ordering-violation guard was added beyond the brief.** `source_seq`
records *emission* order, which equals *training* order only if the producer emits
in order. When a producer's sequence and its declared step positions disagree —
which a deferred or batched flush can cause — `compare()` abstains with
`producer_sequence_position_conflict` rather than manufacturing precedence from
emission order.

# ARCHITECTURE CHANGES FROM PHASE 0

| # | Change | Why |
|---|---|---|
| 1 | **`message` promoted to an envelope field** | `WARNING`/`ERROR` need text outside `metadata`; Phase 0 had it and the first implementation omitted it |
| 2 | **`priority` on the event, not in the queue** | the drop policy must not parse metadata to decide what to evict |
| 3 | **`parent_event_id` and `span_kind` added** | the only provable cross-producer happens-before witness besides a shared sequence |
| 4 | **`run_id`/`producer`/`source` default to `None`, not `""`** | `None` = absent/fill; `""` = explicitly wrong. The observer fills the former and rejects the latter, so integration bugs surface |
| 5 | **`flush()` waits for writer idle, not just an empty queue** | found by the 1M benchmark: two events were neither written nor dropped when stats were read |
| 6 | **Sampling gates computation, not just emission** | `would_emit()`; the per-parameter norm cost 880 µs and was computed then discarded on 9 of every 10 steps |
| 7 | **Detrending added to loss *and* gradient detection** | Phase 0 specified robust z-scores; measurement showed an exponential decay makes the window MAD measure the trend, and heavy tails make a Gaussian z fire on noise |
| 8 | **Gradient criterion is peak-relative, not z-primary** | the brief named "relative change against historical baseline"; implementing it as the primary test fixed two real false positives |
| 9 | **`incidents/evidence.py` → `evidence_builder.py`; ordering lives in `schema/`** | one partial-order algebra, not two. Documented deviation from the brief's file list |
| 10 | **`not_correlated` enforcement is a validation rule, not a convention** | `Incident.validate()` rejects an incident with neither negative nor missing evidence |
| 11 | **Data-causation capped at `HYPOTHESIS` by template `max_level`** | enforced in code, asserted by test |
| 12 | **`DetectionResult.detector_errors` added** | `_safe_detect` was swallowing a real bug into "no anomalies" |

Phase 0's core decisions were **confirmed, not revised**: no forks, Parquet +
DuckDB for telemetry, Trackio kept out of the telemetry path, T2/HTA/NNsight/DCGM/
Flight Recorder deferred. The one Phase 0 design that required real revision was
the statistical shape of the detectors — robust z-scores alone are insufficient for
decaying, heavy-tailed training curves.

# KNOWN LIMITATIONS

Each is a statement of what was **not** verified, not a caveat about what was.

**Scope**
1. **Single process.** Every end-to-end run is one rank. The `CONCURRENT_OR_UNKNOWN` ordering paths are unit-tested but no real two-rank incident has been produced.
2. **No Trackio integration.** Not started. The Phase 0 decision (presentation only) is documented; the code does not exist.
3. **No cross-run comparison.** Specified in Phase 0, not implemented.
4. **No general correlation engine.** `build_evidence` probes a fixed set of six signals. Phase 0's lag-distribution correlation with Benjamini-Hochberg correction is **not implemented**; the fixed-probe version is a strict subset.
5. **Incidents are not persisted.** They serialise to JSON and are recomputed on every `diagnose`.
6. **No replay**, so no data-causation claim can ever exceed `HYPOTHESIS`.

**Measurement**
7. **Overhead budgets not met** on small workloads: +13.3 % core on a 4 ms step.
8. **No GPU measurement.** Everything is CPU/MPS on an Apple M2 Max.
9. **No production-scale measurement.** The largest workload is 12 layers at d_model 256.
10. **~0.8 ms of the largest-workload overhead is not attributed** to any component I measured.
11. **Per-layer query is 692 ms** for 800k rows — a known slow path.
12. **Cold-cache query latency not measured.** All queries ran warm.

**Correctness confidence**
13. **Thresholds are uncalibrated.** Conservative defaults, not fitted; no labelled incident corpus exists.
14. **The healthy-corpus false-positive claim rests on one 400-step scenario** plus one real 130-step run.
15. **`LOSS_DIVERGENCE` is untested on a realistic converged-then-rising curve.**
16. **Multi-rank producer identity is unexercised in practice.**
17. **`torch.compile`, AMP/grad-scaler, and FSDP are untested.**

# PHASE 2 RECOMMENDATION

**Do not add a single new diagnostic capability until the three gaps below are
closed.** Phase 1 proved the chain works; Phase 2's risk is dilution, not
capability.

**Order, with the reason for the order:**

1. **Attribute the remaining 0.8 ms/step and close the core overhead budget.**
   The budget failure is the only unmet numeric gate, it is small, and every later
   phase adds cost on top of an unmeasured baseline. Do this first and re-run
   `benchmark_overhead_scaling.py`.
2. **Persist incidents and add cross-run comparison.** `diagnose` currently
   recomputes everything, so an incident is not a durable object and two runs
   cannot be compared. Phase 0's `not_correlated` bucket is far more useful with a
   healthy baseline run to compare against.
3. **Implement the Phase 0 correlation engine** (windows per incident type, lag
   *distributions*, the conditional-recurrence test, Benjamini-Hochberg correction,
   and the multiplicity denominator). The fixed-probe version in `build_evidence`
   is a subset; the full version is what makes a *shard* hypothesis testable rather
   than merely mentionable.
4. **Then, and only then, the replay primitive.** Replay is the only mechanism that
   converts data-correlation into data-causation, and it is the gate on promoting
   any `data.*` hypothesis above `HYPOTHESIS`. Phase 0 already identified the
   pattern to generalise: TorchTitan's `SDCReplayer`.
5. **After that, multi-rank.** The ordering algebra is already correct for it and
   explicitly refuses to guess; what is missing is a real two-rank run to test
   against. This is a correctness exercise, not a feature.
6. **Diagnostics last**, in the order DCGM → HTA → Flight Recorder → NNsight. Each
   is a `WRAP` with a named adapter boundary already specified in Phase 0, and each
   converts an incident type currently reported as `symptom_only` into one with an
   attributable cause.

**What Phase 2 must not do:** add an LLM agent before the deterministic engine's
precision is measured on real incidents. The renderer is honest precisely because
it cannot invent; an agent layered on top of an uncalibrated detector set would
launder low precision into confident prose.
